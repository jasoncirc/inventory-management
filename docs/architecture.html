Factory Inventory Management System

Architecture overview: a Vue 3 single-page dashboard backed by a stateless FastAPI service that serves and filters JSON-file mock data held in memory. No database, no authentication, no persistence.

System architecture

Browser-side layers on the left, server-side layers on the right. The browser talks to the API directly across origins (CORS is wide open); Vite does not proxy API calls.

Data flow: a filter change

The canonical round trip. Every filtered view follows this path; the only server-side work is list comprehension over in-memory lists.

01
User picks a filter
FilterBar writes to a shared ref in useFilters.
02
View reacts
A watch on the four filter refs calls the view's load function.
03
Build request
getCurrentFilters() maps Location to warehouse, Period to month. api.js drops any value of 'all'.
04
Filter in memory
apply_filters(), then filter_by_month() on order_date.
05
Validate & return
response_model serialises through Pydantic to JSON.
06
Render
Raw response goes into a ref; computed derives KPIs and chart series; the template re-renders.

Example request

# Filters: Period = Q3-2025, Location = Tokyo, Category = Sensors
GET /api/orders?warehouse=Tokyo&category=Sensors&month=Q3-2025

# main.py
filtered = apply_filters(orders, warehouse, category, status)
filtered = filter_by_month(filtered, month)
#   'Q3-2025' -> ['2025-07','2025-08','2025-09']
#   substring match against order_date
return filtered   # validated as List[Order]

Data model

Seven JSON files loaded once at startup. Dimensions shared across datasets: 3 warehouses (San Francisco, London, Tokyo) and 5 categories (Sensors, Actuators, Controllers, Power Supplies, Circuit Boards).

FileRecordsKey fieldsRelationships
inventory.json32sku, warehouse, category, quantity_on_hand, reorder_point, unit_costLow stock when on_hand <= reorder_point
orders.json250order_number, status, order_date, total_value, items[], warehouse, categoryitems[] reference inventory SKUs
demand_forecasts.json9item_sku, current_demand, forecasted_demand, trenditem_sku to inventory.sku
backlog_items.json4order_id, item_sku, quantity_needed/available, priorityorder_id to orders; joined with purchase_orders
purchase_orders.json0backlog_item_id, supplier_name, quantity, statusSets has_purchase_order on backlog
spending.json3 sectionsspending_summary, monthly_spending, category_spendingPre-aggregated, static
transactions.json56recent spending transactionsStatic

Server-derived values: dashboard KPIs (inventory value, low-stock count, pending orders), quarterly and monthly report aggregates, and the backlog has_purchase_order flag. Everything else is passed through as stored.

Observations from the code

Gaps found while mapping the system. Worth knowing before you build on it.

Client calls endpoints that do not exist. api.js defines getTasks, createTask, deleteTask, toggleTask, createPurchaseOrder and getPurchaseOrderByBacklogItem, but main.py has no /api/tasks or /api/purchase-orders routes. Calling them would return 404 or 405. Tasks currently come from mock data in useAuth.
Backlog view is not routed. views/Backlog.vue exists and loads data, but main.js registers no /backlog route and the nav has no link to it.
Reports bypasses the API client. Reports.vue calls axios with a hard-coded URL instead of going through api.js, so the base URL is defined in two places.
Hard-coded year. Quarter mapping (QUARTER_MAP and the quarterly report) only recognises 2025. Orders from other years are silently left out of quarter filters and reports.
Demo-only security posture. No authentication, CORS allows all origins, and the server binds to 0.0.0.0, so it is reachable from your local network while running.
